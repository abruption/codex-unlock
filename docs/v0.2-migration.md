# v0.2 integration and migration boundary

This document defines the supported transition from `codex-unlock` 0.1.1 to
0.2.x. It is an integration contract, not a promise that internal JavaScript
modules are stable.

## Verified v0.1.1 baseline

Version 0.1.1 was released from commit
`a0b2f0765e95ecd3f138540970e66c5dfa84f1dd` and is the hardened baseline for
the 0.2 line. It added fail-closed handling for observation errors, bounded
diagnostic subprocesses, exact process-exit evidence, lock-file identity and
ownership checks, cross-home native-lock detection, and post-signal unknown
states. The supported runtime range remains Node.js `^22.13.0 || ^24.0.0` on
the verified macOS and Linux combinations in
[platform-support.md](platform-support.md).

Version 0.1.0 is historical. Its release and installation records must not be
used as evidence for the current safety or integration contract.

## What changes in v0.2

The 0.2 line adds three externally relevant guarantees while retaining JSON
`schemaVersion: 1`:

1. The supported automation surface is the CLI and its versioned JSON output.
   The package root and generated `dist/` modules are not a JavaScript API and
   are blocked by package exports.
2. Concurrent unlock attempts for the same canonical Codex home and thread are
   serialized with a private same-user advisory operation lease. A competitor
   is refused and cannot send a second `SIGTERM`.
3. Evidence inspection, pure safety policy, and unlock execution are separated
   internally. Signaling remains behind complete revalidation, but the module
   boundary itself is not public API.

Existing JSON v1 consumers should continue to ignore unknown additive fields,
use the documented process exit code, and never treat
`classification: "live_owner"` as authorization. Only `safeToUnlock: true`
after the tool's complete revalidation can authorize its signal path. See
[json-v1.md](json-v1.md) for nullability, error, and exit-code rules.

## Installation paths

Published global installation:

```bash
npm install --global codex-unlock@latest
codex-unlock --version
codex-unlock --help
```

Ephemeral invocation without retaining a global install:

```bash
npx --yes codex-unlock@latest list
```

Source development:

```bash
git clone https://github.com/abruption/codex-unlock.git
cd codex-unlock
npm ci
npm link
```

Direct global installation from a Git URL is not supported. Some npm versions
omit build-time dependencies while preparing that form of package. Deep
imports such as `codex-unlock/dist/doctor.js` are also unsupported and rejected.

## Deliberately unsupported behavior

The 0.2 safety guarantee does not include terminating shared `app-server`,
Remote Control, daemon, ambiguous, changing, or multiple-lock owners. It does
not delete native lock files, offer a force mode, send `SIGKILL`, automatically
self-update, or claim Windows unlock support. Owner-cooperative release and
handoff remains a separate upstream proposal.

Cached update metadata and outdated-version notices are deferred to the 0.2.1
work sequence. Their cache, network, and failure-isolation contract must be
approved before implementation; 0.2.0 does not perform automatic update
checks or self-modification.
